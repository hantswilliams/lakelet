## 2. T1: a replace that fails leaves the old table (`tables.py`, `catalog/server.py`)

The old order was drop, infer, create. The new one is infer, create under `<name>__lakelet_replace`, drop, rename. Two things made it more than a reorder. **Locations.** The catalog puts a table's files at `warehouse/main/<table name>`; a temporary table named differently would get its own folder, the rename would leave the data under the temporary name for good, and a second replace would collide with it. So the catalog's create rule now strips the suffix: a replace's temporary table shares the final name's folder, the rename moves no data, the old table's files are orphans in the same folder that `expire` sweeps after its grace — which is exactly the state the old drop-and-create left and the orphan sweep was written for. **The interrupted state.** A crash between the drop and the rename leaves the temporary table in the catalog; `tables list` lists it with `interrupted_replace_of` set and the sentence naming `lakelet tables rename`, a new verb that is one catalog commit. `expire` refuses while such a sibling exists, because the two share a folder and the orphan sweep would eat the other's files. A user's table may not end in the suffix (`ReservedName`). `tables attach --replace` (T2) reuses the same order. Six tests in `test_trust_replace.py`: an unparseable file, a failure inside the create, a success with the location unchanged, the reserved name on the CLI, the interrupted state finished by `rename`, and `expire`'s refusal plus a second replace superseding a stale temporary.

## 3. T2: a file rewritten under the same path (`register.py`)

Attach stamps the table with `lakelet.verified-at`; `refresh` and `describe` compare every registered file's size with the manifest's `file_size_in_bytes` and its modification time with the stamp. A mismatch is `ChangedFiles` with the first five named and why (`size 1.2 MB → 3.4 MB`, or `rewritten <time>, after the attach`), `refresh` refuses, `describe` prints the line, the app's detail shows it and turns **Refresh** into **Register again**, which is `attach --replace`. A refresh that found nothing changed moves the stamp forward. **What the brief got wrong.** It said pyarrow's listing carries the ETag; it does not. So a same-size rewrite is caught by its time instead, which means a byte-identical re-upload after the attach reads as changed too — the safe direction, recorded on the page and in the test's docstring. Two seconds of grace absorb S3's second-resolution `LastModified` and a store clock a little ahead. Five tests against Moto and a `file://` prefix, one Vitest for the detail.

## 4. T3: the fourth verdict (`gauge/`, `query.py`, the CLI, the app)

`select * from read_parquet('…')` was Green having read nothing: the plan's `READ_PARQUET` node matched no catalog table and got `bytes=0`. Now only `ICEBERG_SCAN` nodes are attributable; any other scan node (`READ_PARQUET`, `SEQ_SCAN` for a native or temp table, an Iceberg scan no known table accounts for) is `unattributed`, and one such scan makes the estimate `verdict = "none"`, words `Not estimated`, reason `1 scan outside the catalog: read_parquet`, a hollow dot on the CLI, grey in the app, never Green. The statement runs, history records `none`, `gauge export` drops such runs from the calibration file, `lakelet run` builds a `none` model and says so, and `count(*)` alone over a file is still honestly Green because DuckDB answers it from the footer (a `COLUMN_DATA_SCAN`, no scan at all; the test says so). The app's `Verdict` type gained `'none'`; `verdictSentence`, `planSummary`, the gauge line, the DAG and the Gauge screen's words all know it, and the scatter excludes it. `core-nightly.yml` runs the TPC-H accuracy assertion with `LAKELET_TPCH=1` at 03:17 UTC. ## 5. T4: the schema version, and the recovery contract (`schema.py`, `/docs/recovery`)

One `ensure_schema` for both stores: a new file gets the version and `written_by`; a newer version refuses with the sentence (`this project's catalog was written by a newer Lakelet (0.2.0, schema 2); this is 0.1.0, which reads schema 1 — upgrade Lakelet, or open the project with the version that wrote it`) and the file is untouched; an older one runs the numbered migrations, of which there are none, through a mechanism the test exercises with a fake one. The CLI maps it to exit 1. `/docs/recovery` was written from the tests, not the other way round: `test_recovery.py` has one test per sentence (a copy restored to the same path is a complete backup; the derived folders can be deleted; a failure mid-import leaves the previous snapshot; both databases are WAL; a full disk names the disk; `expire` never removes a file the current snapshot references). The full-disk sentence needed a change to make it true: the catalog answered a bare 500 to an `OSError`, so DuckDB reported `HTTP 500` and nothing else; the server now maps `ENOSPC` to 507 with the OS's own sentence and *the catalog was not changed*, and DuckDB's message carries it.

## 6. T6: what a browser can send (`catalog/server.py`)

One ASGI middleware on the shared app, before any route: a `Host` that is not `127.0.0.1`, `localhost` or `::1` is 403 (DNS rebinding); an `Origin` header on `/v1` at all, or one on `/api` that CORS does not allow, is 403; a body that is not `application/json` on a POST, PUT or PATCH is 403. The brief said the `Origin` refusal on `/api` was "redundant with the token but free"; it is not free — the app's own requests carry `Origin: tauri://localhost` — so `/api` allows the origins CORS allows and refuses the rest, and the middleware takes that list from `Project.open`. Four tests, including one request of each shape an engine sends going through unchanged; the DuckDB, pyiceberg, S3 and API suites are the wider proof. One lesson cost an hour: the first version was a Starlette `BaseHTTPMiddleware`, which passed every pytest and then broke the app's Esc in Playwright — that middleware wraps every response in a streaming shim, and the query route's handling of a client that goes away mid-stream depends on the raw cancellation reaching the generator. It is a plain ASGI middleware now (`LoopbackOnly`), and the Esc spec passes again. `PRIVACY.md` (which D22 promised in September 2026 and which did not exist) and `SECURITY.md` are written and a test reads them for the words the server actually enforces. The security contact is Hants' commit address; his call whether another goes there.

## 7. T5: the moved folder (`relocate.py`)

The spike said yes, and found the thing nobody had written down: **a position-delete file names, in every row, the data file it deletes from by absolute path.** Relocating the metadata alone gave 1500 rows where 1490 were right — the deletes silently stopped applying, and both DuckDB and pyiceberg agreed on the wrong number. So `relocate` rewrites four kinds of file: each manifest (pyiceberg's `ManifestWriter`; sequence numbers and the manifest's content kind copied back, because the writer assigns fresh ones and a delete manifest read as a data manifest counted its rows as data), each manifest list, each position-delete Parquet file with its `file_path` column translated and its bounds updated, and the metadata file as a new version the catalog is moved to. Detection needs no marker: a local table whose metadata is missing at its recorded location and present at the same relative path under this folder is a moved table, and `moved_from` names the old root. `tables list` lists such tables marked `needs relocate` rather than failing; `/health` carries `moved_from`; the Tables screen shows the sentence with a **Relocate** button (the brief said the welcome screen, but the detection happens when the sidecar opens the project, which is after the welcome screen); the ninth sidecar is a project moved after its table was written. Every snapshot is kept — the test time-travels to the first — and the old files are orphans `expire` sweeps. Four pytest, one Playwright.
